# Slack 双 Agent 工作室

让用户在一个 Slack 频道发起任务，Codex 与 Claude 使用各自现有 CLI、登录、会话和工作目录完成工作。协调程序管理阶段、证据、暂停恢复和交付；不把两个名字映射到同一个模型。

## 从当前状态开始

先区分新机器搭建、维护已有实例，还是调整工作流程。已有实例时确认其目录、监听端口、运行任务和配置状态，在原实例上工作；不要启动争抢同一频道的副本。

- 新建：读 [搭建与 Slack 接入](references/setup.md)，通过 `scripts/materialize.mjs` 将 `assets/coordinator/` 复制到独立运行目录。skill 资源目录不直接充当运行目录。
- 两种模式、讨论结论、追问与交付：读 [协调协议](references/orchestration.md)。
- 核对 CLI、账户、模型来源或排查 401：读 [身份与运行环境](references/cli-identity.md)。
- 配置联网、依赖、SSH、浏览器或桌面：按需读 [能力模块](references/capabilities.md)。
- 验收、升级、恢复与诊断：读 [验证与维护](references/verification.md)。

## 不可混淆的两个维度

`independent` / `collaborate` 决定双方如何工作；`discussion` / `deliverable` 决定用户需要什么结果。

| 任务目标 | independent | collaborate |
| --- | --- | --- |
| 制作成果 | 各自独立完成 → 冻结并展示两份初稿 → 互评修订与比较 → 吸收优点形成最终整合版 → 对方复查 | 双方计划 → 交换并约定分工 → 各自制作 → 整合 → 对方复查与必要修订 |
| 讨论决策 | 各自先形成意见 → 交换理由和证据 → 提出明确结论 → 对方确认同一版本 | 在共同上下文中交换观点、解决分歧，最终确认同一结论 |

讨论只需要推荐、理由、条件、未知和仍有的分歧。不要为了“交付”创建文件。达不到一致就说明争议并停在待处理状态。制作成果保留独立版本、比较意见和最终版，不能只展示整合版。

## 协调时保持这些约束

1. **先理解追问再调度。** “结果在哪”“展示一下”“现在怎样”直接返回既有结果或状态；解释问题用已有证据回答。实际修改才修订现有最终版并复查；明确要求重做才走完整流程。分类不确定或失败时澄清，不能默认重跑两位。
2. **独立意味着先不偷看。** 初稿完成前不把对方答案或目录交给 worker。双方从同一 Git 提交或两个独立空目录出发；写入只在自己的目录，交叉评审只读。
3. **确认具体结果。** 最终验收读取实际文件、测试输出或真实应用状态，不能只信作者的 `done`。讨论结论绑定版本摘要，由另一位明确确认；安排下一阶段不算未解决缺陷。
4. **保留会话和检查点。** 同一任务每位 worker 复用自己的 CLI session。恢复先完成未完成阶段；查看结果不改变轮次、epoch 或修改要求。阻塞阶段不缓存为成功。
5. **有条件地结束。** 评审轮数、调用超时有上限；超限且有实质问题就报告待处理，不伪称成功。身份、权限、认证或能力缺失时暂停，给出具体恢复动作。
6. **明确告知用户。** 通过验收后由 Codex 在原讨论串通知并广播 `@发起者`，包含实际成果入口或共同结论，以及“在此讨论串继续提出修改；新任务在频道另发”的说明。

## 实现与环境边界

- 使用现有 `codex exec` 与 `claude -p`，不替换成模型 API 调用，不全局重写用户 CLI 配置。版本、provider、账户与真实模型分别核对。
- 默认仅监听 `127.0.0.1:7417`。两个 Slack bot 名称使用 Codex、Claude；主入口是 `@Codex`，用户只需发一次，程序直接交接，不靠 bot 互相 mention。
- 使用显式频道和用户允许列表，默认只申请公开频道所需权限。凭据通过本机私有配置输入，不进入 skill、Git、Slack 报告或 worker 提示词。
- 能力按需启用，安装 skill 不等于授予全部桌面、服务器或外部发布权限。同一 OS 用户的目录划分不是硬隔离。
- Mac 桌面模块复用已安装且可用的官方 Computer Use 入口；它依赖当地运行环境和原生审批，不是 skill 自带的通用桌面服务。不可用时说明前置条件，不编造支持或绕过审批。

## 完成这次系统工作时

报告运行目录、真实 CLI 身份核对结果、已启用且实测的能力、Slack 连接范围、验证结果及仍需用户处理的事项，提供可直接使用的频道命令。区分模拟回归、真实 CLI、真实 Slack 与 GUI 验证；旧机器历史验收不证明新部署可用。

分享本 skill 只发布代码、通用示例和文档。`scripts/check-package.mjs` 检查文件清单、哈希、符号链接和明显凭据；不要把 `.local/`、会话、截图、用户任务或已有配置上传。
