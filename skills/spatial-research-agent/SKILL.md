# 通用科研协作

## 第零步：从空白会话确认调用来源

首次启动先在当前聊天向用户展示并询问「每个角色使用哪个客户端、哪个型号；这组来源和型号可以吗？」等用户明确选择后再派工。模型和客户端分别记录。不要把上次会话的选择、已安装客户端或同名模型当成本次来源授权。若用户已在本次请求明确给出整组，复述后采用；只补问未指定的项。选定的路由沿用到本项目的返工和后续轮次。

| 角色 | 建议的独立来源 | 型号示例 |
|---|---|---|
| Claude 主控、独立规划和独立验收 | 用户自己的 Claude Code 登录 | Claude Opus 5.5（`--claude-model claude-opus-5-5`） |
| Gemini 独立规划和独立验收 | Antigravity 的 Google 登录 | Gemini 4 Neon High（`--gemini-model gemini-4-neon-high`） |
| 独立规划、执行、修改、自检与结果解读 | 当前 Codex 会话；单轮脚本启动目标机器上的 Codex CLI | 当前配置，或明确指定 `--codex-model` |

只有用户明确选择让 Antigravity 提供 Claude 时才用 `--claude-agy-model`。某一入口认证失败、型号不可用或额度耗尽时，保留已完成阶段，告知哪个来源失败；换客户端或账号须由用户另选。路由记录表示请求的客户端与型号；服务返回的实际型号或登录方式可另记，实际扣费以各账户账单为准。

### 冷启动验收

在新终端或全新主持会话中，清空本次任务的选择，保留用户原有登录。从仓库根目录运行以下预览；它只询问并打印路由，不读研究数据、不连 SSH、不发模型请求。

```sh
python3 skills/spatial-research-agent/scripts/research.py --show-routing
```

1. 验证先看见 Claude 来源选项，以及 Gemini 和 Codex 各自的固定入口；再填写各角色型号。对话主持者应在聊天中提问，不能为用户抢先填 `--use-defaults`。
2. 选择 Claude Code 后检查预览为 `claude / agy / codex`。改选 Antigravity 的 Claude，再次检查主控为 `agy`。非交互运行须传各角色选择；用户明确接受其余默认值时可加 `--use-defaults`。
3. 用模拟 CLI 检查实际执行参数和失败路径。Claude Code 失败应停在该阶段，其他订阅不接管。把预览、模拟调用和真实服务回报分开记录。预览通过后，正式调用继续使用已确认的同一组参数。

把研究问题、可共享材料、已有证据、预期交付物和验收标准写入任务说明。按研究类型选择证据：文献综述可提供纳入标准和原文，理论研究可提供定义、假设和推导，计算研究可提供数据、代码和运行配置。实验项目可整理设计与观测记录；需要人员或仪器实际完成的步骤应标记待执行。每轮规划时，三位规划者接收相同材料。

首轮选模型时，Claude 一并询问是否有本次任务的限制；用户已说明的直接沿用。计算任务可以问最多同时用几张卡、累计多少 GPU 小时；任何项目都可以设截止时间、费用或轮数。只询问与任务有关的项目。都可以留空，明确说不设或跳过后直接按研究目标推进，不填默认数字，也无需再问。并行卡数、累计用量和轮数分别记录。未设置数值上限不扩大原任务范围或付费授权。

## Claude 主持的五步循环

一次任务沿用用户选定的三方模型。启动时明确研究目标、完成标准、允许的工作范围及用户选填的限制；把任务模式和这些约束带入后续各轮。调用本 skill 的 Claude 会话负责主持循环。现有 research.py 提供单轮辅助流程，运行到报告即退出，脚本本身尚未实现下述双审和跨轮恢复。采用五步循环时由主持会话分别调度各阶段，复用脚本中的 CLI 和 SSH 调用方式；调用整个脚本会提前汇总，也可能重复执行任务。

1. **独立规划。** Claude、Gemini 和 Codex 在各自的新会话里看同一份原始任务、约束及上一轮已核实的证据。三者分别说明已有结果支持什么、下一步做什么、如何判断达标。三份规划首稿封存后，由主控读取并派工。
2. **Claude 汇总派工。** 主控读取三份规划原稿，说明采纳的方案、分歧和取舍，写明本轮任务、方法、输入、已设限制、应交付的文件及验收标准，再交给 Codex。
3. **Codex 执行、自检并解读结果。** 按任务模式执行，记录实际方法、输入、产物位置与自检结果；涉及计算或调度时记录配置、命令与作业号。对排队或运行中的作业，主持会话用同一作业号查询进度，完成后读取产物。等待期间停留在第三步。每轮产物就绪后，Codex 在本轮 Codex 目录单独保存一份执行者意见，指出结果支持什么、有哪些替代解释或局限、下一步最值得做什么，并引用对应证据。事实性自检记录另存，供双审复核。
4. **独立验收。** 给两个全新会话分别提供同一份验收标准、Codex 自检记录，以及允许共享的实际研究产物和来源材料。Claude 和 Gemini 在看到对方意见前各交一份报告，说明每项标准的证据、复算结果、未通过或无法核实的项，以及下一步建议。远程文件应先在服务器核对，再提供可共享的证据；只有 Codex 的文字摘要或不可访问的路径时，相应项标记为未核实。
   主持会话在发起双审前冻结同一份证据包。两位审核者分别使用全新、互不继承历史的会话，输入相同；Claude 审核者也与先前派工的 Claude 主控分开。证据包可含运行配置、实际结果、预先约定的标准和 Codex 自检记录，排除 Codex 的执行者意见及两位审核者的判断、摘要和草稿。审核输入通过提示传入或挂载同一份只读副本；若提供文件读取能力，只开放该证据包。仅切换工作目录不能保证隔离。由主持端在两位审核者都无权读取的位置分别保存首稿；串行运行也遵循同样规则。两份首稿都返回并封存后才交给主控比对。若一方调用失败，保留另一方已封存的首稿，重试时仍只发送原证据包。若证据有实质更新，为双方开启新一轮独立审核。
5. **Claude 总验收并决定转向。** 两份独立首稿封存后，主控一并读取 Claude、Gemini 的验收意见和 Codex 的执行者意见，记录三方的共识、分歧，以及采纳或暂缓各项建议的证据理由，对照原目标决定下一步。目标达到则交付。实现错误或产物缺失则列出具体问题，回第三步修正并再次双审。实验有效但研究问题尚未回答，且下一轮仍在授权和预算内，则带着本轮证据回第一步。出现超预算、目标变更或必须由用户决定的取舍时暂停，说明需要决定什么。三方有分歧时按证据裁决，保留无法消除的不确定性。

第五步也是可选的人工检查点。展示本轮结论、拟采取的动作，以及已设限额的剩余额度，在派发下一项工作前检查当前会话已收到的用户指示。有新指示就记录并按其调整；已要求暂停时停在检查点。没有新指示时，按原先授权和预算推进，无需逐轮等候确认。以后才到达的指示在收到后处理，并说明已有作业处于什么状态。

首轮明确怎样算完成。每次派工或返工前核对研究目标及用户实际设定的限制。达标则收尾；到达已设上限仍未达标，报告缺口。未设数值上限时，以任务完成、缺少新证据、具体阻碍或需要用户决定的范围变化为停止依据。

## 项目归档与主控日志

同一个科研项目复用一个归档根目录。开始或恢复时先读项目说明和主控日志，定位当前轮次与最近一次交接。由主持会话在首次使用时建立以下结构，后续按轮追加：

```text
项目/
├── 项目说明.md             # 目标、完成标准、模型选择、授权范围、可选限制
├── 主控日志.md             # 全项目按时间追加的交接与决策索引
└── 轮次/
    └── 001/
        ├── 共同输入/       # 实际交给三位规划者的同一版任务与背景
        ├── Claude/         # 独立规划与独立验收的输入、答复及首稿
        ├── Gemini/         # 独立规划与独立验收的输入、答复及首稿
        ├── 主控/           # 综合方案、实际派工单、验收标准、本轮决定
        ├── Codex/规划.md    # Codex 在派工前提交的独立方案
        ├── Codex/尝试-01/  # 派工回执、脚本、结果、自检.md、执行者意见.md 和作业号
        └── 验收证据/尝试-01/  # 本次冻结的事实材料和来源索引，双审共用
```

每次尝试使用同一编号串起执行、双审和决策。例如，主控从 Codex/尝试-01/ 选取事实性自检与产物编入验收证据/尝试-01/。执行者意见留在 Codex 目录，直到两份首稿封存才汇总。两份验收原稿分别归入 Claude/尝试-01/ 和 Gemini/尝试-01/。主控在 主控/尝试-01/决定.md 链接该版证据、三份意见，写明采纳理由和下一步，并把决定路径追加到项目日志。返工时递增尝试编号，恢复时使用日志里的轮次和尝试编号。旧项目保留原目录，日志可直接引用已有文件。

每次交接保存实际发送的任务文本和实际返回的答复；相同附件可引用本轮冻结副本。主控日志每条写明时间、轮次、阶段、发送方、接收方、输入与输出的相对路径、状态、决定和理由。Claude 的独立评审材料归 Claude 目录，Claude 作为主控作出的综合判断归主控目录。返工沿用当前轮次，给每次尝试单独编号，原始统计表、失败记录和首稿均保留。只有回到第一步重新规划时才新开一轮。

归档根目录由主控管理。独立规划与验收期间，各参与者使用独立的临时工作区，仅取得本阶段共同材料；依据前述隔离要求封存首稿，规划阶段三份、验收阶段两份交齐后再发布到本轮角色目录。主控日志在此之前只记提交状态，不透露首稿内容。大型数据、权重及受限材料保留在授权位置，索引记录服务器别名、路径、版本或校验值，以及生成它们的作业号。可共享的小型统计表与核验结果随轮次归档。

作业提交后立即登记作业号。转阶段时记录已设限额的用量和下一步。中断恢复时先核对已有产物及同一作业的状态；提交状态不明时依据唯一任务标记查调度记录，避免重复提交。连续运行依赖主持进程保持活动。相同问题反复返工仍无新证据时，记录阻碍并暂停。

## 单轮辅助脚本

需要 Python 3.8+，以及已登录且可在终端非交互运行的 claude、agy（Google Antigravity CLI）和 codex。个人 Google 账号请按 [Antigravity 官方指南](https://antigravity.google/docs/getting-started?tab=cli) 安装 agy，运行 agy 登录。命令在 PATH 中可见时，从仓库根目录运行：

```sh
python3 skills/spatial-research-agent/scripts/research.py brief.md --project /path/to/research-project --out runs/pilot-01
```

安装成 skill 后使用本文件同目录下的 scripts/research.py。默认让 Codex 只读核对项目并规划。用户要求实际执行实验时加 --execute，让 Codex 在指定工作区内写入。Gemini 评审默认使用 Gemini 4 Neon High；通过 agy models 查看可用型号，用 --gemini-model 指定其他型号。选择 default 时，Claude Code 和 Codex 分别沿用各自的模型配置。Claude 和 Gemini 在临时目录工作，主控依据任务说明与执行报告整合结论。项目数据路径提供给 Codex，任务说明及各阶段文字输出可能传给对应的模型服务。

单轮脚本每次运行使用新的输出目录。依次保存原始任务、Claude、Gemini 和 Codex 各自的规划稿、综合方案、Codex 报告与最终结论。运行中断时查看最后完成的阶段和终端错误；重新执行前核对已生成的实验文件或已提交的作业。最终汇报引用项目中的证据路径，并区分已观察的结果与待验证的假设。

## 在集群上实际执行

当用户要求跑实验、实现改动或产出结果时，选择执行模式。模型选好后，三方先独立规划，主控在本机汇总派工，执行阶段通过 SSH 把任务交给服务器上已登录的 Codex CLI。它在指定项目目录使用 workspace-write，能编写脚本、运行分析并按集群规则提交作业。远程登录环境需要能找到 codex。若授权、沙箱或调度失败，报告具体原因和已完成阶段。交付前核对真实输出；对排队作业保留 job ID 并根据用户要求追踪到完成。

```sh
python3 skills/spatial-research-agent/scripts/research.py brief.md \
  --ssh-host my-cluster --remote-project /project/my-study --execute \
  --out runs/experiment-01
```

可以复用下文的 --control-socket。三方只需一个 SSH 通道；Claude 和 Gemini 仍在本机调用。SSH 工作区由服务器端 Codex 自身的沙箱约束。

## 复核远程服务器已有结果

三个模型的 CLI 都运行在本机。已有评估终表时，先确认作业状态、回单对应的实验条件和文件更新时间，再选取这次决策需要的汇总文件。通过已配置的 SSH 别名读取指定文件，Codex 在本地 evidence 副本中复核。每个文件使用不同的文件名。示例从仓库根目录运行：

```sh
python3 skills/spatial-research-agent/scripts/research.py brief.md \
  --ssh-host my-cluster \
  --remote-file /project/eval/results/paired.csv \
  --remote-file /project/eval/results/receipt.json \
  --out runs/remote-review-01
```

SSH 默认复用别名配置的连接。已有独立 ControlMaster 时加 `--control-socket /path/to/socket`。账号需要 MFA 时，在终端完成一次该别名的认证，再复用连接。远程复核模式只读取列出的文件；文件和来源清单保存在本地运行目录。若原始材料需留在服务器，在服务器完成获准的核对，再提供可共享、可追溯的证据。说明本次直接查验了什么，以及哪些结论还需要原始材料。

用户已选择让 Antigravity 提供 Claude 时，可用 `agy models` 核对账号可选的 Claude 型号，并显式加 `--claude-agy-model claude-opus-5-5-medium`。这会将主控的输入及执行报告经 Antigravity 发送给选定型号。在五步循环中，Gemini 规划时接收共同背景，验收时另接收同一份可共享的实验产物与验收标准。
