# 通用科研协作

**模型设计原则（Less is more）。** 每轮从足以回答研究问题的最简基线出发。各规划者指出基线的具体不足；Claude 派工时只选验证当前假设所需的改动，执行者按单实现。提出额外模块、损失项、超参数或训练技巧时，说清它解决什么问题，以及怎样用简单对照检验贡献。验收时，若收益落在评估波动范围内或现有证据无法区分两种方案，保留简单版本为默认，把复杂方案记作待验证假设。

本文件是常驻规则。每条 `workflow.py` 命令都打印下一步卡片（命令、要读和要写的文件及上限），`guide` 随时重印；按卡片走，卡片不够时才按文末索引读对应的一个文件，不预读 references，不读 `scripts/` 源码。

## 启动

1. **定档。** 主控先判断档位，把档位和理由告诉用户，用户可改。档位和理由连同研究目标、完成标准、授权范围和限制写进 `项目说明.md`，带入后续各轮（写法见 templates.md）。
2. **确认团队和路由。** 首次启动先在聊天中展示本档默认团队（标准档三方规划、Codex 执行、三方审阅；轻量档 Codex 执行、Claude 一方审阅），再问：「独立审阅用几个 agent、是哪几个？（标准档再问独立规划用几个、是哪几个）谁执行？各用哪个客户端、型号、推理强度？」能用提问工具时，把人数做成选项。每多一方，token 和耗时大致按比例增加。顶级路由和降级路由一起确认，用户明确选择后再派工。不要把上次会话的选择、已安装客户端或同名模型当成本次授权；用户已在请求里给出整组时复述后采用，只补问未指定项，审阅人数没说就必须问。某入口认证失败、型号不可用或额度耗尽时，保留已完成阶段，说明哪个来源失败；换客户端或账号须由用户另选。
3. **询问限制。** 一并询问与任务相关的限制：最多同时用几张卡、累计 GPU 小时、截止时间、费用、轮数。用户已说明的直接沿用；都可以留空，说不设就按目标推进，不填默认数字，不再追问。各项分别记录。未设数值上限不扩大原任务范围或付费授权。
4. **计算任务先查资源。** 用到集群时，在第一份计划之前查清资源，写进 `项目/计算资源.md` 并放进共同输入。
5. **开轮。** 运行 `workflow.py 项目 1 1 guide` 看开轮卡片，按卡片 `init`（同时初始化进度页并绑定本会话用量），把页面路径告诉用户。

## 两个档位

每轮开始，主控用一两句话说明「这轮要解决什么、为什么现在做、做到什么就结束」，作为共同输入；用户已指定就直接采用。盘点、复盘、总结、新计划、补测、长训练都可以独立成轮。两档都由 `scripts/workflow.py` 驱动固定交接，主控只在需要判断时写派工、放行意见和决定。

**轻量档（工程）：** 交付物是代码、工具或流水线，验收可测试，没有开放的科学方法问题。
1. 主控按计划模板自写计划，不做独立规划；
2. 派工；
3. 执行者（默认 Codex）试跑 → 主控审代码并放行 → 正式运行；
4. 默认由 Claude 角色一方审阅，可用 `init --reviewers` 改；
5. 主控裁决。

**标准档（研究）：** 五步循环，默认三方。
1. **独立规划。** 各规划者（默认 Claude、Gemini、Codex）各在新会话读同一份任务、约束和上一轮已核实的证据，各写一份计划。
2. **主控派工。** 读齐封存的计划原稿，说明采纳的方案、分歧和取舍，写派工单。
3. **执行。** 执行者（默认 Codex）先只实现并试跑，交付后停下。主控审代码（可用 `/code-review`）、对照派工单核对输出，记录通过、返工或证据不足及依据；通过才正式运行。返工和缺证都递增尝试号。正式产物就绪即冻结，不等执行者自检。
4. **独立审阅。** 各审阅者同时独立审阅第三步的同一版冻结交付。
5. **主控总验收。** 读齐全部报告，逐项采纳、暂缓或驳回并写证据理由，决定交付、下一轮或暂停。各方分歧按证据裁决，保留无法消除的不确定性。下一轮从第一步重新开始。

**团队。** 规划者、执行者和审阅者在 `init` 时定，返工沿用，只在新一轮改。标准档少于两方规划或审阅会失去独立对照，只在用户同意时这样配。

**升档。** 轻量档出现会改变结论的方法分歧时，主控升为标准档：在新一轮 `init --tier standard`，并在主控日志和项目说明写明理由。

子命令、参数和各步细则见 workflow-commands.md，各类文稿的模板和字数上限见 templates.md。

## 模型与推理强度

以下是推荐默认值，启动时仍由用户确认。

- **工程／轻量档：** 实现用 Codex `gpt-6.2-sol`、`max`；代码审查用 Claude Code `claude-opus-5-5`、`xhigh`。只有出现重大分歧时，才用更高一档的模型裁决：routes 里加 `Adjudicator`（例如 Fable 5.2、`xhigh`），运行 `adjudicate`。
- **研究／标准档：** 首轮，以及问题定义或方向改变的轮次，团队各成员都用顶级型号。问题结构化后，后续轮次可换成启动时已确认的降级路由来审阅和推进。结构化指：目标、指标和方法已稳定，上一轮审阅没有重大分歧，本轮是增量工作。切换在新一轮用 `init --routes 降级.json`，理由记入主控日志。出现新的重大分歧或方向改变时回到顶级路由。
- **裁决建议。** 审阅封存后，若分歧足以改变结论，或下一步将投入大量计算，用 Adjudicator 取得裁决建议；最终由主控记录采纳理由并派工。主控日志登记每次深度调用的阶段、型号和触发原因。
- 选定的团队和路由沿用到本项目的返工和后续轮次，只按上述规则或用户要求在新一轮切换。

## 证据隔离与首稿封存

- 规划者收到同一版问题和必要背景；执行者收到派工单和相关输入；审阅者收到同一版标准、实际改动、测试结果和冻结证据。每次交接核对各方可见范围与版本一致。
- 规划和审阅各在独立的 `mktemp -d` 临时目录运行，不继承派工会话，不接收任何一方的自检、判断或草稿。只开放证据包；临时目录本身不保证隔离。
- 首稿写到项目内只有主控能访问的持久目录（可先写临时文件，再原子封存）。同一阶段的首稿全部交齐后，才复制到各角色目录并记录 SHA-256。此前主控日志和进度页只记提交状态，不透露内容；等待时只看退出码和文件大小，不打开内容，也不读各方运行日志或会话记录（如 Codex 会话日志，里面含草稿）。
- 单方失败时保留其他首稿，只用同一证据重试失败方；半份输出不算交付。证据变化就对新版本重新发起审阅。
- 第四步只审阅：审阅者及其子代理都不运行代码、命令或测试，不补算、不改文件、不提交作业。主持者用文本输入或只能读冻结材料的权限交给审阅会话，关闭执行和写入入口。缺新实验时在报告里提出。
- 子代理受同样的证据隔离和项目预算约束，不接触未封存的意见，不代主控放行或裁决。

## 预算与停止

- 首轮明确怎样算完成。每次派工或返工前，核对研究目标和用户实际设定的限制。
- 派工前按分区的真实分配粒度估算节点小时和 GPU 小时，计入在途作业。超出并发卡数或剩余额度时，不向上取整后提交；先缩小方案或请用户决定。到达上限即停止派工，报告缺口。
- 需要 GPU 的计算就申请 GPU。GPU 作业失败时查明原因、修好、在 GPU 上重交，**不许退到 CPU**；**登录节点上不许跑任何计算**。同一问题失败 3 次仍无进展，停下报告。
- 未设数值上限时，以任务完成、缺少新证据、具体阻碍或需要用户决定的范围变化为停止依据。相同问题反复返工仍无新证据时，记录阻碍并暂停。
- 出现超预算、目标变更或必须由用户决定的取舍时暂停，说明需要决定什么。
- 第五步也是可选的人工检查点：展示本轮结论、拟采取的动作和已设限额的剩余额度，派下一项工作前检查用户的新指示。有新指示就记录并调整；已要求暂停就停在检查点；没有就按原授权和预算推进，不逐轮等确认。之后才到的指示收到后处理，并说明已有作业的状态。

资源估算、按节点派工和试跑资源检查见 compute.md。

## 主控上下文与交接

- 可恢复的研究事实存在项目目录，不靠对话记忆。主控的型号、职责和项目授权跨会话沿用。用户可指定上下文预算；不要把模型窗口容量当作每次调用的目标长度。
- 到阶段边界（计划封存、试跑放行、审阅封存），或主控上下文变大时，运行 `workflow.py … handoff`：写不超过 40 行的 `交接单.md`，更新 `恢复点.md`，然后在新的主控会话继续（终端里 `/clear` 后输入 `/research-agent 从恢复点继续`）。接手者先读交接单，复述下一步、理由和依据；有缺口才读对应原件。
- 交接单和任何摘要都不得省略授权限制、失败记录和互相矛盾的证据。冻结输入用路径和 SHA-256 引用。
- 主控在新会话启动，不从其他会话分叉。工具定义随每次请求重发，长项目建议按 routing.md 的精简命令在终端启动主控。
- 长文件（代码、日志、超长回执）交给子代理读，只回传结论和证据位置。不要把大段输出打印进主控上下文；同一份派工单、报告或工具输出只注入一次。
- 等待作业、读退出码、归档和刷新进度交给脚本；状态变化、出错、需要放行或有研究分歧时才需要主控判断。

恢复点字段和断点续跑见 archive-and-recovery.md，子代理和用量核算见 context-and-usage.md。
